<objective>
Deliver the heart of Phase 2: `GET /v1/observations` with the D-API-01 resolution resolver auto-routing across the raw `observations` hypertable + the `obs_hourly` and `obs_daily` continuous aggregates, RFC 7807 range-validation, per-row provenance and quality flag exposure (API-11), case-insensitive variable alias resolution, and cursor pagination integrated with the HMAC cursor from plan 02-01.

Purpose: This is the single endpoint that makes Phase 1's ingested data queryable for time-series researchers. After this plan a real user can fetch "the last 7 days of air_temperature for station X" in a single curl, get sub-second response (CAGG-routed for >=1h ranges), iterate through pages, and see exactly which source the data came from.

Output: One router file, one query file, one schema file, integration tests against a real TimescaleDB testcontainers instance (since this is the most database-dependent endpoint in the phase).

Vertical MVP framing: This plan plus plan 02-03 together give a user the full "query" capability end-to-end. Plan 02-05 adds export streaming + rate-limit + OpenAPI enrichment. After plan 02-04 the entire JSON read path is feature-complete.

Resolution decision (D-API-01, locked):
- delta < 1h  -> table = `observations`,  resolution = `raw`
- 1h <= delta < 1d -> table = `obs_hourly`, resolution = `hourly`
- delta >= 1d -> table = `obs_daily`, resolution = `daily`

Range limits (D-API-02, locked):
- raw -> max 7 days
- hourly -> max 90 days
- daily -> max 5 years (5 * 365 = 1825 days)

Default range (D-API-03): `end = now`, `start = now - 24h`.
Half-open semantics (D-API-04): `WHERE observed_at >= $start AND observed_at < $end`.

| Boundary | Description |
|----------|-------------|
| Untrusted query params -> asyncpg SQL (table name selection, station_id, variable filter, time range, cursor) | SQL injection vector; table name interpolation is the most dangerous since it is the only string-typed identifier that touches SQL |
| Cursor token -> resolution + filters validation | Tampered cursor could attempt to bypass range limits or jump rate-limit budgets (rate-limit lands in plan 02-05) |
| Untrusted time range -> DB load | Multi-year raw queries would scan ~50M rows (PITFALLS.md #12); range validation is the only guard |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-04-01 | Tampering | Table-name interpolation in SQL — any user-controlled path to selecting `observations` vs other tables | mitigate | `_TABLE_TO_SQL: dict[str,str]` with frozenset of allowed keys `{"observations","obs_hourly","obs_daily"}`; `resolve_table` returns ONLY one of these three constants; never f-string-interpolates user input into a table name; verify gate asserts the keyset |
| T-02-04-02 | Tampering | SQL injection via station_id (path-int), variable (alias-resolved), start/end (datetime), cursor (HMAC-validated) | mitigate | All parameters use asyncpg `$1, $2, ...` parameterization; station_id is FastAPI-typed `int`; variable goes through `resolve_variable_alias` which DB-queries with `$1`; start/end are `datetime`; cursor goes through HMAC decode first |
| T-02-04-03 | Denial of Service | Multi-year raw-resolution query scanning 50M+ rows | mitigate | `validate_range_for_resolution` rejects raw > 7 days, hourly > 90 days, daily > 5 years per D-API-02 -> 400 ProblemDetail before any DB query is issued |
| T-02-04-04 | Denial of Service | Cursor pagination loop opening many connections | mitigate | Single asyncpg connection per request (via pool.acquire); rate-limit 30/min/IP for /v1/observations delivered in plan 02-05 |
| T-02-04-05 | Information Disclosure | Source license leak via response — accept | accept | License is intentionally public per CC-BY/CC-BY-NC attribution requirements; surfacing the license IS the compliance mechanism (API-11 + research note on per-row provenance) |
| T-02-04-06 | Tampering | Cursor replay across changed time-range (e.g. cursor from a 6h hourly query reused on a 30-day daily query) | mitigate | Cursor payload carries `res` (resolution) AND `fhash` (filters_sha256); router rejects with 400 `urn:climatepulse:filter-changed` when either mismatches |
</threat_model>
