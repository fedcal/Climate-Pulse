<objective>
Close the WMO variable dictionary gap discovered after Phase 1 ingestion left ~97k rows/day warned as `unknown:Bxxxxx`. Phase 2 owns the fix per D-API-17 (locked decision):

1. `B04001-B04006` (year/month/day/hour/minute/second BUFR components) are redundant with `observed_at` -> silently drop at the adapter (no log warning, no row emitted).
2. `B07031` (height of barometer above mean sea level) is station metadata, not an observation -> extract into the in-memory `Station.elevation_m` accumulator so the next station upsert pass populates `stations.elevation_m`.
3. `B13215` (precipitation quality flag): when value != 0, record the SUSPECT state on the next emitted precipitation observation by adding a per-station context that the row builder consults; when value == 0, drop without emitting.

Purpose: Zero data loss for the 7 core variables, zero log noise from the 97k/day skipped rows, station elevation now populated from the source rather than left null, and Phase 2 source-health metrics (`/v1/sources/status` in plan 02-03) report cleaner ingestion health.

Output: Modified ARPA Emilia adapter, new unit tests asserting drop/extract behavior, re-recorded VCR cassette assertion that the 7 core variables emit byte-identical observations as before.

Scope note: This plan touches ONLY `packages/core/climatepulse_core/adapters/arpa_emilia.py` and tests. It does NOT touch any FastAPI / API surface. It runs in Wave 1 with full file-ownership isolation from plan 02-01, enabling parallel execution.

No new requirement IDs are claimed: D-API-17 is an internal data-quality scope adjustment carried in CONTEXT.md (not a numbered v1 requirement). The fix preserves API-11's per-row provenance + quality flag exposure (delivered in plan 02-04) by improving the underlying data.
</objective>
